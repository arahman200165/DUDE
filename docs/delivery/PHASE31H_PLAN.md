# Phase 31H implementation decisions

Status: implementation started at Milestone 720 and is being completed through Milestone 728; the phase exit gate remains pending. No tools are executable on Android until Phase 31I. [Acceptance evidence and required passes](PHASE31H_ACCEPTANCE.md) govern closure.

- **PD-075 — Android build baseline.** Expo SDK **57.0.26**, React Native **0.86.3**, React **19.2.3**, Hermes, Expo Router and local Continuous Native Generation/Gradle. SDK libraries follow the installed Expo `bundledNativeModules.json`. The root remains Node 24 / npm 11.19 with one lockfile; mobile consumes compiled workspace package exports. Android's supported floor is API 29 and its target is API 36; compile/target SDK are pinned to API 36; build tools follow the SDK template. JDK 17 is the native toolchain requirement. The system currently has JDK 23; a checksum-verified portable JDK 17 is available under ignored `tmp/mobile-toolchain/` for local verification without a system install.
- **PD-076 — Preview identity and delivery.** The initial package is `io.github.arahman200165.dude.preview`, display name **DUDE Preview**, `dude` deep-link scheme. No EAS/cloud build, vendor backend or OTA runtime; `updates.enabled` is false. Generated Android files remain untracked. Native changes live in local Expo modules/config plugins.
- **PD-077 — Mobile host boundary.** TypeScript/TSX gates prohibit Angular, Electron, Node built-ins and Node-only workspaces, browser-only storage/DOM globals, application-source imports and source aliases into packages. The shell permits the lightweight `@dude/tool-engine/core/registry/tool-search` subpath, with no other engine imports. Native ports are mobile-owned; shared registry, tokens, policies and sync contracts remain package-owned.

SDK alignment includes root npm overrides for `react-native-worklets` **0.10.1** and `react-native-reanimated` **4.5.1**: Expo Router's wildcard optional peers otherwise hoist newer incompatible native versions beside the declared workspace versions. This creates mismatched Babel/runtime instances. Update these overrides together with the owning mobile dependency pins during an SDK upgrade.

The root build-tool dependencies explicitly pin `@babel/generator` **7.29.7**. Worklets 0.10's plugin requires this module without declaring it; with Angular's generator 8 hoisted, generating Expo's Babel 7 TypeScript AST failed in `Printer.TSFunctionType` during the first Android export. This build-only compatibility pin makes that undeclared lookup deterministic; Angular retains generator 8 under its owning Babel packages. It grants no application import permission.

### Scope and durable behavior

- **PD-078 — Native identity and pinned transport.** Explicit QR/paste enrollment and trust review use the existing signed device protocol. Kotlin keeps Ed25519 seeds outside JavaScript, with Bouncy Castle signing and an AES-GCM Android Keystore wrapping key. A dedicated pinned HTTPS/WebSocket client authenticates TLS before application bytes, rejects cleartext/redirects and bounds requests/responses. Tokens stay in memory; durable enrollment receipts omit pairing codes, proofs and tokens. Android advertises `secure-storage` only, keeps recovery trust off and retains internal key-bearing device-kind compatibility.
- **PD-079 — Contract-first category privacy.** The Hub advertises optional `syncCategoryFiltering: true`; validated optional categories filter snapshot/change records and tombstones before serialization, preserving unfiltered callers and global cursor semantics. Android requires this capability and only requests consented favorites/settings. Enabling a category takes a fresh filtered preview.
- **PD-080 — Isolated durable contexts.** App-private Expo SQLite uses exclusive transactions and numbered structural migrations with downgrade refusal. Standalone, one enrolled environment and read-only archives are separate. Entity edits/outbox coalescing commit together; claimed operations retain stable IDs across uncertainty and cannot be overwritten by newer edits. The shared 10,000-row ceiling applies per isolated context, so retaining an archive cannot block an unrelated environment. Credentials/recovery/database files are excluded from cloud backup/device transfer.
- **PD-081 — Android foreground driver.** Shared policies and limits are reused by a mobile-specific driver; desktop orchestration stays in place. First sync offers per-category Merge (union, Hub wins overlapping IDs), Use Hub (recovery copy plus confirmation) and Keep local (publish local values). Foreground-only single-flight cycles use 16-record pull pages, 4 MiB response limits, shared push limits and bounded backoff. Staged snapshots preserve pending edits and refuse authority/history regression; their initial revision remains the catch-up cursor.
- **PD-082 — Recovery and lifecycle boundaries.** Revocation freezes cached data. Disconnect deletes the local signing credential after a recovery copy and retains an archive, warning if offline unenrollment left a Hub row. Credential-free recovery export/import preserves device identity/cache/pending IDs; re-pair uses a fresh signing key and repeats consent. Cache clearing, pending-attempt discard and conversion use expiring, single-use action/context/revision-bound confirmations. Failures do not silently reset storage or discard edits.
- **PD-083 — Preview delivery and acceptance.** Local Gradle packaging requires explicit signing configuration; protected CI preview keys are separate from disposable emulator acceptance keys. Version name matches root major/minor plus full `master` commit count, and Android version code is that count. APK/AAB/checksums join the existing draft-release writer; no EAS, Play or OTA path is added. Local automated regressions, native instrumentation and bundled-app journeys on API 29/API 36, and disposable-key APK/AAB builds have passed. Protected signed-install, physical connectivity/replay/re-pair, manual accessibility and first CI evidence remain required before closing 31H. DUDE 2.0 remains gated at 31I.
