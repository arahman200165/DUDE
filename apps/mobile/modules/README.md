# Local Expo modules

Local modules are discovered by Expo autolinking during Android prebuild. `dude-hub` owns the Android signing identity and a dedicated pinned HTTPS/WSS client. It never installs a global trust manager or a crypto provider.

`prepareKey(environmentId, installId)` creates a new opaque reference. A per-reference Android Keystore AES-256-GCM key wraps a random Ed25519 seed in `noBackupFilesDir`; `deleteKey` removes both the wrapped file and Keystore key. `publicKey` returns 32 raw public bytes as base64url. `signEnrollment` and `signChallenge` accept only the corresponding validated protocol fields and return 64-byte base64url signatures. Neither a private key nor a generic signing API crosses into JavaScript. `randomBytes` provides bounded native randomness.

The lightweight Bouncy Castle implementation is pinned to **1.86** ([release](https://www.bouncycastle.org/resources/new-release-bouncy-castle-java-1-86/)); OkHttp is pinned to **4.12.0**. The client's own trust manager verifies the leaf SPKI during handshake before HTTP headers or WebSocket upgrade. Pin-only identity matches the desktop transport, including self-signed certificates reached by an IP/name other than the certificate name. Cleartext and redirects are refused; calls have a 15-second timeout, JSON bodies a 4-MiB limit, and realtime messages a 16-KiB application limit. The pin derivation helper hashes certificate SPKI, not certificate bytes. Expo's debug-only manifest permits cleartext Metro development traffic; the dedicated Hub client still refuses cleartext in every build variant. The production manifest disables cleartext, excludes app data from cloud backup and device transfer, and blocks external storage, read-media, microphone and overlay permissions.

`src/hub/types.ts` defines the persistence port consumed by enrollment/session adapters. Pending receipts contain public identity, expected authority and key references; no pairing code, proof or bearer token is durable. Lost enrollment acknowledgements recover through a new signed challenge and `deviceSelf`, without replaying a code. Unconfirmed keys stay pending until an explicit discard. Tokens remain in memory, share one refresh, and redeem a fresh challenge once when an expired/used challenge is rejected. Repeated proof rejection is recoverable `key-rejected`; only an authenticated revocation event/close confirms revocation. Any authority epoch change requires reviewed reconnect.

Native instrumentation under `dude-hub/android/src/androidTest` covers independent Node/shared-contract Ed25519 vectors, actual Keystore reload/deletion, missing Keystore material, HTTP/WSS wrong-pin peers receiving zero application bytes, and redirect/cleartext/response-size refusal. After prebuild, the local Gradle task is `:dude-hub:connectedDebugAndroidTest`; root phase verification owns the emulator pass. Pure adapter tests run through `vitest.mobile.config.mts`.
