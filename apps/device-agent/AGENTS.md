# AGENTS.md — apps/device-agent/

The resident per-user **Device Agent** (PD-026): a separate Node process (`src/main.ts`, bundled by `node scripts/build-device-agent.mjs` / `npm run device-agent:compile` to `dist/electron/device-agent.js`, and built into the SEA `dist/agent/dude-agent.exe` by `scripts/build-sea.mjs`) that owns the SQLite database `userData/device-store/dude-device.db` through `node:sqlite` and serves the closed RPC table over a per-user named pipe (`@dude/agent-pipe`: length-prefixed JSON, bytes as base64, server-first HMAC handshake). Run it as `--store-dir <dir>` (required) or `--version`. It writes `agent.pid` and `agent-pipe.key` in the store directory.

- `src/agent.ts` (`runAgent`) is the service. Standalone start: once listening, the agent reads `<storeDir>/agent-config.json` (`src/agent-config.ts`: the last desktop-supplied `appInfo` and `capabilities`, including the cached `secureStorage` flag) and opens the store immediately, so it runs with no desktop; with no usable file it waits for the first authenticated connection and opens from that config. Every authenticated connection whose config differs rewrites the file (atomic replace); the open store is not reopened. The agent reads the Windows MachineGuid itself (`src/machine-fingerprint.ts`), so clone detection never depends on the desktop (the `machineGuid` in the handshake config is ignored). The store is shared by every later connection and requests are answered in order per connection. A connection with no usable config while the store is closed gets a placeholder (health and shutdown only) that is not cached.
- RPC lifecycle methods: `store.checkpoint` folds the WAL and keeps running (the desktop sends it before detaching on quit); `store.shutdown` checkpoints, closes and exits (explicit stop, reset, version skew, or quit when the user does not keep the agent resident); `store.quarantine` (unavailable store only) moves the DB files aside from inside the agent because Windows cannot rename files the agent holds open.
- The desktop spawns the agent detached and unreferenced (`apps/desktop/device-store/agent-transport.ts`), so it survives the desktop. On quit a packaged build with "start at sign-in" on detaches and leaves it running; an unpackaged build shuts it down. A per-user sign-in entry (Task Scheduler `ONLOGON` task, or the HKCU Run key when a standard user is denied the task) starts it with `--store-dir`; see `apps/desktop/AGENTS.md`. The agent version is the build-time `__DUDE_VERSION__` (`dev` unbundled); the desktop restarts a packaged agent whose version differs.
- Only Electron main talks to it (never the renderer). It is NOT the privileged "Device Agent" execution boundary of SYSTEM/SECURITY_ARCHITECTURE until it gains those capabilities; see the [decision log](../../docs/history/DECISION_LOG.md#phase-31c-implementation-decisions).
- No `electron` or `@angular/*` imports, and nothing here is imported by `apps/web` (`npm run check:boundaries` enforces both). Allowed workspace deps: persistence, sync, contracts, domain, shared-types, sqlite-store, agent-pipe, api-client.
- Schema changes happen only through new numbered migrations in `src/store/migrations/`. Never edit a shipped migration (checksums are verified); bump `minReaderVersion` only for changes older builds cannot read.
- Hub authority (Phase 31G, PD-071/PD-073): `src/hub/authority-check.ts` compares every `hello` with the enrollment (instance id, then `transferred`, then a lower `authority_epoch`; reasons `instance-changed`, `transferred`, `epoch-lower`) and the connection state becomes `authority-changed` with the sync phase `needs-reconcile`, before any push or pull; it runs at the start of every connect and in refresh, token, welcome and revoke confirmation, so a changed Hub is never read as a revoked device. The persisted `sync_reconcile_required` flag (`cursor-ahead`, `epoch-lower`, `history-regressed`, in `store/repos/sync-state.repo.ts`) blocks sync the same way; `sync/rebase.ts` refuses to delete or move the cursor when an acknowledged local entity is newer than the snapshot (a regressed entity is never un-acknowledged). Recovery snapshots are taken once per changed authority with the prefixes `authority-changed`, `sync-reconcile`, `rebase` and `reconnect`.
- `hub.reconnect` (`{pairingString, acknowledged: true}`, `reconnectDevice` in `src/hub/enroll.ts`) is the only way out: allowed from `offline`, `connecting`, `authority-changed`, `untrusted-tls`, `revoked` and `incompatible` (or while the reconcile flag is set), never from `online` or standalone. It takes a `reconnect` snapshot, replaces the enrollment (same device id, new key) and calls `resetHubBookkeeping`, which resets only sync bookkeeping (revisions, merge bases, cursor, first-sync progress, the reconcile flag, outbox `based_on_revision`) and never entities, outbox ops or settings; the first-sync preview (Merge, Use Hub, Keep local) then decides. Device-store migration 0005 adds `hub_enrollment.authority_epoch`.
- Every journaled entity change commits its row and its coalesced outbox op in one transaction (`src/store/entity-commit.ts`).
- Specs run in `npm run test:electron`; `src/testing/crash-writer.ts` is bundled by the crash spec and hard-killed to prove durability.
