# @dude/hub-backup

Private internal package. Portable encrypted backup file format for the self-hosted Hub (`.dudebackup`). It uses no Node built-ins or host globals: the passphrase key-derivation function (the Hub injects Node's Argon2id), the random source and the clock are injected through `BackupDeps`.

Layout: `DUDEBKUP` magic, a big-endian u32 header length, a plaintext JSON header (reader information only: versions, KDF name and parameters, salt, cipher, chunk size, stream id), then length-prefixed XChaCha20-Poly1305 chunks. Each chunk's nonce is the stream id plus a chunk counter and its associated data is the SHA-256 of the header plus a final-chunk flag, so reordering, truncation, header tampering and a wrong passphrase all fail authentication. The manifest and every file live inside the encrypted stream. Consume compiled exports; never import application source.

Backup v2 (Phase 32-SS1, `backup-v2-*.ts`) streams with memory bounded by one chunk per open object. A repository is a set of write-once objects: `repo` (plaintext header plus a random master key wrapped under the Argon2id passphrase key, so a passphrase change re-wraps only this object), encrypted `packs/<id>` and `manifests/<backupId>` (NDJSON records: head with the 31G authority fields, files, blobs keyed by HMAC-of-SHA-256 dedupe identity with extents that may point into earlier backups' packs, an end record). Each object has its own HKDF key bound to its name, a nonce of object id plus chunk counter, associated data binding the header hash, counter and final flag, and a trailer with counts and a tag chain. `createRepository(..., { masterKey })` reuses one master key across repositories (the Hub keeps one for all its destinations, Milestone 847). `writeBackupExport` produces the single-file `.dudebackup` v2 form; `openBackupFile` reads v1 and v2 files. Every v2 header carries `minReaderVersion` 2, so v1 readers refuse it. Design and limits: `docs/architecture/SECURITY_ARCHITECTURE.md` (backup v2 format, Milestone 846).
